Tokenización de operaciones

La tokenización es un servicio que permite generar un código único (token) asociado a una tarjeta del cliente, que posteriormente puede utilizarse para lanzar operaciones adicionales sin necesidad de volver a introducir los datos de la tarjeta. 

Este sistema puede emplearse tanto en presencia del cliente (operaciones online autenticadas) como en operaciones sin presencia del cliente (pagos recurrentes, a plazos, etc.).

Es importante destacar que según la directiva PSD2, las operaciones "one-click" en las que el cliente está presente online deben requerir siempre autenticación o alguna de las exenciones permitidas (TRA, LOW, etc.), no debiendo enmascararse como operaciones MIT (Merchant Initiated Transactions).

Para utilizar la tokenización, el comercio debe:

  • Solicitar la activación del servicio a través de su entidad financiera.
  • Emplear la comunicación online, pues el token generado se entregará durante este proceso.

El token generado está ligado a un comercio y usuario específico, no siendo válido para otros comercios o usuarios.

 

 

Proceso de Tokenización

El servicio de tokenización consta de dos pasos principales:

  1. Registro de Tarjeta
  2. Pago con Token

 
1.Registro con tarjeta

Este paso inicial es similar a una operación estándar, pero con algunos ajustes específicos.

Campos requeridos para la llamada

MerchantID []

Identifica al comercio, proporcionado al darse de alta (requerido, longitud máxima: 9).

AcquirerBIN []

Identifica la entidad financiera, proporcionado al darse de alta (requerido, longitud máxima: 10).

TerminalID []

Identificador del terminal (requerido, longitud máxima: 8).

Num_operacion []

Identificador único de la operación (requerido, longitud máxima: 50).

Importe []

Importe en céntimos. Los dos últimos dígitos representan céntimos (requerido, longitud máxima: 12).

TipoMoneda []

Código ISO-4217 de la moneda (978 para euros)(requerido, longitud máxima: 3).

Exponente [Tipo]

Identifica al comercio, proporcionado al darse de alta (requerido, longitud máxima: 9).

Referencia [Tipo]

Identifica al comercio, proporcionado al darse de alta (requerido, longitud máxima: 9).

Cifrado [Tipo]

Identifica al comercio, proporcionado al darse de alta (requerido, longitud máxima: 9).

URL_OK [Tipo]

URL para operaciones exitosas (requerido, longitud máxima: 500).

URL_NOK [Tipo]

URL para operaciones fallidas (requerido, longitud máxima: 500).

Idioma [Tipo]

Identifica al comercio, proporcionado al darse de alta (requerido, longitud máxima: 9).

Descripción [Tipo]

Identifica al comercio, proporcionado al darse de alta (requerido, longitud máxima: 9).

Idusuario [Tipo]

Identifica al comercio, proporcionado al darse de alta (requerido, longitud máxima: 9).

Exencion_SCA [Tipo]

Identifica al comercio, proporcionado al darse de alta (requerido, longitud máxima: 9).

Tipo_COF [Tipo]

Identifica al comercio, proporcionado al darse de alta (requerido, longitud máxima: 9).

Inicio_Rec [Tipo]

Identifica al comercio, proporcionado al darse de alta (requerido, longitud máxima: 9).

Fin_Rec [Tipo]

Identifica al comercio, proporcionado al darse de alta (requerido, longitud máxima: 9).

Frec_Rec [Tipo]

Identifica al comercio, proporcionado al darse de alta (requerido, longitud máxima: 9).

Importe_Max_Rec [Tipo]

Identifica al comercio, proporcionado al darse de alta (requerido, longitud máxima: 9).

Firma [Tipo]

Identifica al comercio, proporcionado al darse de alta (requerido, longitud máxima: 9).

Datos_acs_20 [Tipo]

Identifica al comercio, proporcionado al darse de alta (requerido, longitud máxima: 9).

Firma_acs_20 [Tipo]

Identifica al comercio, proporcionado al darse de alta (requerido, longitud máxima: 9).

 

Una vez validada la operación, el comercio recibirá los siguientes datos adicionales:

Caducidad []

Fecha caducidad de tarjeta (AAAAMM) (longitud máxima: 6).

Idusuario []

Usuario asociado (longitud máxima: 50).

Token []

Token generado ("ERROR-75" indica fallo) (longitud máxima: 16).

MMPP_TX_ID []

Identificador único universal para futuras operaciones (longitud máxima: UUID).

 
2.Pagos con Token

Permite pagos adicionales con el token ya registrado.

URLs para Pago con Token:

  • Pruebas: https://tpv.ceca.es/tpvweb/tpv/compraToken.action
  • Producción: https://pgw.ceca.es/tpvweb/tpv/compraToken.action
 
Campos adicionales requeridos

URL_OK []

Valor fijo “NOAPLICA” (requerido)

URL_NOK []

Valor fijo “NOAPLICA” (requerido)

Idioma []

Valor fijo "XML" (requerido)

idusuario []

Usuario asociado (requerido)

Token []

Token generado previamente (requerido)

MMPP_TX_ID []

Identificador UUID de operación original (requerido)

Ejemplo de llamada

https://tpv.ceca.es/tpvweb/tpv/compraToken.action?MerchantID=106900640&AcquirerBIN=0000554000&TerminalID=00000003&URL_OK=NOAPLICA&URL_NOK=NOAPLICA&Importe=005&Idioma=XML&TipoMoneda=978&Exponente=2&Num_operacion=7279973403351516000&Cifrado=SHA2&Firma=d148…

La respuesta será proporcionada en formato XML o JSON según el idioma especificado.

Uso compartido del Token entre comercios

Por defecto, los tokens son válidos solo en el comercio que los generó. Para compartir tokens entre múltiples comercios, el comercio debe contactar a su entidad para configurar esta opción.

Control de Cambios

  • v6.7: Se añade campo mmpp_tx_id obligatorio.
  • v6.8: Campos Exencion_SCA y Tipo_COF pasan a opcionales.
  • v6.9: Corrección del campo Num_operacion.
  • v6.10: Ajustes en idioma, URL_OK y URL_NOK.
  • v6.11: Eliminación del campo MMPP_TX_ID en el registro inicial.
