Pago por eMail

El pago por email de Cecabank es una solución rápida y segura que permite cobrar a tus clientes sin necesidad de una web o TPV físico. Solo tienes que generar un enlace de pago y enviarlo por correo: ellos pagan, tú cobras. Ideal para ventas a distancia, presupuestos o cobros personalizados.

Enlace de pago personalizado

Genera links con importe, concepto y vencimiento adaptados a cada cliente.

Cobro sin web

Ideal para negocios sin tienda online o para ventas directas.

Seguimiento de pagos

Consulta en tiempo real el estado de cada operación.

Entorno seguro

El cliente paga en una página protegida, cumpliendo con los estándares PCI-DSS.

Entornos y endpoints

Disponemos de dos entornos independientes

Sandbox

Creado para que puedas probar nuestra solución en un entorno seguro e igual que el de Producción.

Te permitirá comprobar que tu integración se ha realizado correctamente, probando todas las funcionalidades que tenemos disponibles: tipos de autenticación (frictionless, challenge) y resultados (autorizada, denegada).

Te ofrecemos un listado de tarjetas y cuentas para realizar pruebas.

Producción

Procesa pagos reales con la misma latencia que Sandbox.

Alta disponibilidad y monitorización 24x7.

Acceso a un conjunto configurable de tarjetas y cuentas para validar escenarios reales en producción.

Paso a paso Generación enlace de cobro

A continuación se explican los pasos para generar el enlace de cobro

Paso 1

Preparar los parámetros (método generarPlantillaExt)

Nombre Tipo Obligatorio Descripción
modo String ✔ Acción. Ejemplo: generarPlantillaExt
merchantId String ✔ 9 dígitos. Ejemplo: 106900640
acquirerBin String ✔ 10 dígitos. Ejemplo: 0000554000
terminalID String ✔ 8 dígitos. Ejemplo: 00000003
numOp String ✔ Nº pedido (≤ 50 car.). Ejemplo: 9995967081915474000
importe Integer ✔ Céntimos (1 → 1,00 €). Ejemplo: 100
moneda Integer ✔ Código ISO-4217. Ejemplo: 978
idioma Integer ✔ 1 = ES, 6 = EN, … Ejemplo: 1
cifrado String ✔ Hash SHA-256. Ejemplo: SHA2
token String ✔ Se exige “si” salvo que la entidad permita saltar token.
Ejemplo: si / no
fechaCaducidadPago String ✘ Fecha límite DD/MM/AAAA. Ejemplo: 01/06/2029
directoBizum String ✘ Abrir Bizum directo. Ejemplo: si / no
codigoQR String ✘ Devolver QR en Base 64. Ejemplo: si / no
firma String ✔ Hex minúsculas. Ejemplo: SHA256(clave + merchantId + acquirerBIN + terminalId + fechaCaducidadPago + numOp)

Paso 4

Consultar o anular (opcional)

Use los otros modos (xmlPagosMailExt, anularPagoMailExt) con la misma firma SHA-256 y el ID_CIFRADO devuelto.

Recomendaciones

  • No envíe el enlace clicable por e-mail/SMS: facilite al cliente la URL corta + el token por canales separados.
  • Use fechaCaducidadPago para limitar la validez.
  • Conserve ID_CIFRADO, numOp y la respuesta online para devoluciones o auditorías.
